## Запуск

### 1. Поднять PostgreSQL в Docker

```bash
docker compose up -d
```

При первом запуске PostgreSQL автоматически создаст 4 базы данных (`vehicles`, `races`, `hotels`, `organization`) и наполнит их данными из соответствующих `schema.sql` + `data.sql`.

Параметры подключения:

| Параметр | Значение  |
|----------|-----------|
| Host     | localhost |
| Port     | 5432      |
| User     | postgres  |
| Password | postgres  |

### 2. Подключиться GUI-клиентом (опционально)

Подойдёт любой клиент для PostgreSQL: **DBeaver**, **pgAdmin 4**, **TablePlus**. После подключения в дереве сервера будут видны 4 базы данных.

### 3. Выполнить запрос задачи

**Из GUI:** открыть нужный `task-NN.sql`, переключиться на соответствующую БД, запустить.

**Из терминала:**
```bash
docker compose exec db psql -U postgres -d vehicles -f /repo/01-vehicles/task-01.sql
```

## Описание баз данных и реализованные задачи

### 1. Транспортные средства (`vehicles`)
4 таблицы: `Vehicle` (общий справочник производителей/моделей) и три специализированные — `Car`, `Motorcycle`, `Bicycle`. Связаны через `model` (FK на `Vehicle.model`).

- **Задача 1.** Фильтр: спортивные мотоциклы с заданными характеристиками. JOIN + WHERE + ORDER BY.
- **Задача 2.** Объединение трёх выборок разных типов транспорта в один результат через `UNION ALL`, с приведением NULL для отсутствующих колонок у велосипедов.

### 2. Автомобильные гонки (`races`)
4 таблицы: `Classes` (классы авто), `Cars`, `Races`, `Results` (связка авто–гонка с позицией).

- **Задача 1.** Авто с минимальной средней позицией в каждом классе. CTE + подзапрос с `MIN` через кортеж в `WHERE ... IN`.
- **Задача 2.** Авто с глобальной минимальной средней позицией. Один SELECT с `ORDER BY ... LIMIT 1`.
- **Задача 3.** Все авто из классов с наименьшей средней. Три CTE: статистика класса, «победившие» классы, статистика авто.
- **Задача 4.** Авто со средней лучше средней по классу (классы только с ≥2 авто). Два CTE.
- **Задача 5.** Авто из классов с «низкой» средней (> 3). Условный счётчик через `COUNT(*) FILTER (WHERE ...)`.

### 3. Бронирование отелей (`hotels`)
4 таблицы: `Hotel`, `Room` (тип и цена), `Customer`, `Booking` (с датами заезда и выезда).

- **Задача 1.** Клиенты с > 2 бронирований в разных отелях. `STRING_AGG` для списка отелей, средняя длительность как `AVG(check_out - check_in)`. `HAVING` с двумя условиями.
- **Задача 2.** Пересечение «активных» (> 2 броней в разных отелях) и «крупных» (> 500 $). Один SELECT с тремя условиями в `HAVING`.
- **Задача 3.** Категоризация отелей по средней цене номера через `CASE` и определение предпочитаемого типа клиента по правилу приоритета (Дорогой > Средний > Дешёвый) через `MAX(rank)`. Два CTE.

### 4. Структура организации (`organization`)
5 таблиц: `Departments`, `Roles`, `Employees` (с самореференцией `ManagerID` — иерархия подчинения), `Projects`, `Tasks`. Все три задачи требуют рекурсивного CTE.

- **Задача 1.** Все подчинённые Ивана Иванова (рекурсивно) + он сам, с проектами и задачами. `WITH RECURSIVE` + подзапросы со `STRING_AGG` для конкатенации проектов и задач.
- **Задача 2.** То же + `TotalTasks` (число задач) и `TotalSubordinates` (только прямые подчинённые) — последние через коррелированный подзапрос.
- **Задача 3.** Сотрудники с ролью «Менеджер» и рекурсивными подчинёнными > 0. Шаблон «root_id + sub_id» в рекурсивной CTE — для каждого сотрудника считается полная глубина его дерева.

## Особенности реализации

- В `02-races/task-05.sql` использован строгий порог `> 3` (как в тексте задачи), что даёт `low_position_count = 1` для Sedan вместо `2` в эталонном выводе — детали в комментарии файла.
- В `03-hotels/task-02.sql` `total_spent` считается как `SUM(price)` без умножения на число ночей — иначе результат расходится с эталоном задания.
